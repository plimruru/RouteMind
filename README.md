# RouteMind

RouteMind — локальный веб-прототип для планирования выездов сервисных бригад.
Он распределяет заявки между подходящими исполнителями, строит порядок визитов с
учётом временных окон и смен, а затем показывает результат на карте. Проект
подготовлен для кейса ЛЦТ 2026.

## Возможности

- загрузка заявок и бригад из JSON;
- проверка навыков, специализации и необходимого транспорта;
- учёт координат, времени в пути, длительности работ, временных окон и смен;
- построение маршрутов, расчёт времени визитов и километража;
- вывод общей статистики и причин, по которым заявку нельзя назначить;
- создание срочной заявки и повторное планирование;
- сравнение результата с простым baseline-алгоритмом.

## Стек

| Часть | Технологии |
| --- | --- |
| Интерфейс | HTML, CSS, JavaScript, Leaflet |
| Локальный сервер и API | Python 3, стандартная библиотека |
| Планировщик | C++20, CMake, nlohmann/json |
| Данные | JSON |
| Карта | OpenStreetMap; OSRM используется для отображения дорожного маршрута |

## Требования

- Python 3.10 или новее;
- CMake 3.20 или новее;
- компилятор с поддержкой C++20: `c++`, `g++` или `clang++`;
- интернет при первой конфигурации CMake: библиотека `nlohmann/json` загружается
  автоматически.

Интернет также нужен для фоновой карты, дорожных линий OSRM и геокодирования
новых адресов. Если OSRM недоступен, интерфейс отображает линии между точками.

## Быстрый запуск
PS1="\u@\h:\w\$ "

В корне проекта выполните:

```bash
cmake -S . -B build
cmake --build build --parallel
python3 frontend/server.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для остановки сервера
нажмите `Ctrl+C` в терминале.

Сервер по умолчанию доступен только локально. При необходимости можно указать
адрес и порт (после этого надо будет открыть [http://127.0.0.1:8080]):

```bash
python3 frontend/server.py --host 0.0.0.0 --port 8080
```

Если папка `build` была перенесена вместе с проектом и CMake ссылается на старый
путь, удалите именно папку сборки и выполните конфигурацию заново:

```bash
rm -rf build
cmake -S . -B build
cmake --build build --parallel
```

## Как проверить демо

1. Оставьте дату `17.08.2026`.
2. Нажмите «Выгрузить заявки».
3. Нажмите «Создать маршруты».
4. Выбирайте бригады над картой и смотрите порядок визитов, время работ и
   объяснение назначения.
5. Откройте неназначенную заявку, чтобы увидеть причину.
6. Через «Новая заявка» добавьте срочное обращение и повторно создайте маршруты.

## Структура проекта

```text
cpp/                 C++-модель, маршрутизация и планировщик
data/                исходные заявки, бригады и координаты
frontend/            веб-интерфейс и локальный HTTP-сервер
docs/                описание алгоритма, данных и демонстрации
output/              пример результата расчёта
scripts/             вспомогательные скрипты, включая геокодирование
```

## Данные и результат

| Файл | Назначение |
| --- | --- |
| `data/requests.json` | Исходные заявки. |
| `data/locations.json` | Координаты заявок. |
| `data/brigades.json` | Навыки, специализации, транспорт и смены бригад. |
| `data/brigade_locations.json` | Стартовые точки бригад. |
| `frontend/user_requests.json` | Добавленные через интерфейс заявки. |
| `output/plan.json` | Результат запуска планировщика из корня проекта. |

Заявки, созданные в интерфейсе, сохраняются в `frontend/user_requests.json`;
исходные файлы из `data/` не изменяются. Время принимается в ISO 8601
(`2026-08-17T09:00:00`) или в формате `HH:MM`, длительность указывается в
минутах, расстояние — в километрах.

## Логика планирования

Сначала обрабатываются наиболее ограниченные заявки: срочные, с меньшим числом
доступных исполнителей и с более узкими временными окнами. Для каждой заявки
планировщик перебирает допустимые вставки в маршруты совместимых бригад и
выбирает вариант с наименьшим приростом пробега, не нарушающий смену и временные
окна. Затем выполняются допустимые улучшения порядка визитов.

Расстояние вычисляется по формуле Haversine, а время пути — по средней скорости
выбранного транспорта. Это упрощение прототипа, поэтому показатели используются
для планирования, а не как навигационные гарантии. Детали приведены в
[docs/algorithm.md](docs/algorithm.md) и [docs/planner.md](docs/planner.md).

## Запуск планировщика без интерфейса

После сборки можно рассчитать план напрямую:

```bash
./build/route_planner
```

Результат будет сохранён в `output/plan.json`. Для расчёта baseline используйте:

```bash
./build/route_planner --baseline
```

## Ограничения MVP

- Перепланирование создаёт новый план для актуального набора заявок и не
  закрепляет уже выполненные визиты.
- Сценарии отмены заявки и недоступности инженера пока не выведены в интерфейс.
- Карта служит визуализацией; расчётные метрики основаны на упрощённой модели
  расстояний и времени в пути.
