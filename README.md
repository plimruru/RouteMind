# RouteMind

RouteMind — локальный веб-прототип для диспетчера выездных бригад. Сервис
распределяет заявки между исполнителями, рассчитывает порядок визитов и показывает
маршрут на карте. Решение подготовлено для кейса ЛЦТ 2026.

## Возможности

- загрузка встроенного JSON-набора заявок и бригад;
- распределение заявок с учётом навыков, специализаций и транспорта;
- учёт координат, времени в пути, длительности работ, временного окна и смены;
- маршрут, время начала работ и пробег для каждой бригады;
- суммарные метрики: задействованные бригады и общий километраж;
- отображение неназначенных заявок с понятной причиной;
- объяснение факторов назначения в карточке маршрута;
- создание срочной заявки и повторное построение плана;
- сравнение с baseline из ТЗ: первая доступная бригада во входном порядке.

## Стек

- интерфейс: HTML, CSS, JavaScript, Leaflet;
- локальный HTTP-сервер и API: Python 3, стандартная библиотека;
- планировщик: C++20;
- данные: JSON;
- карта: OpenStreetMap и OSRM (если есть доступ к сети).

## Быстрый запуск

Требования: Python 3.10+, CMake 3.20+ и компилятор C++20 (`c++`, `g++` или
`clang++`).

```bash
cd /путь/к/RouteMind-develop
cmake -S . -B build
cmake --build build --parallel
python3 frontend/server.py
```

Откройте в браузере [http://127.0.0.1:8000](http://127.0.0.1:8000).
Остановка сервера — `Ctrl+C`.

При первой конфигурации CMake загружает `nlohmann/json`, поэтому нужен интернет.
Для карты также нужен интернет; при недоступности OSRM интерфейс показывает прямые
линии между точками.

Если проект перенесён или распакован в другую папку и CMake сообщает о старом пути
`build`, удалите только папку сборки и повторите команды выше:

```bash
rm -rf build
cmake -S . -B build
cmake --build build --parallel
```

## Демонстрационный сценарий

1. Оставьте рабочую дату `17.08.2026`.
2. Нажмите «Выгрузить заявки».
3. Нажмите «Создать маршруты».
4. Переключайте бригады над картой и просматривайте порядок объезда, время визитов
   и причины назначений.
5. Откройте заявку без бригады, чтобы увидеть причину неназначения.
6. Нажмите «Новая заявка», заполните адрес, окно, навык и длительность. Новая
   заявка считается срочной.
7. Повторно нажмите «Создать маршруты». Интерфейс покажет результат
   перепланирования и изменение назначений.

## Данные

Исходный демонстрационный набор находится в `data/`:

| Файл | Содержание |
| --- | --- |
| `requests.json` | Заявки: адрес, окно, навыки, транспорт и другие атрибуты. |
| `locations.json` | Координаты заявок. |
| `brigades.json` | Бригады, навыки, специализации, транспорт и смены. |
| `brigade_locations.json` | Стартовые точки бригад. |

Новые заявки сохраняются в `frontend/user_requests.json`; исходные данные в `data/`
не изменяются. Время принимается в ISO 8601 (`2026-08-17T09:00:00`) или `HH:MM`,
длительность — в минутах, расстояние — в километрах.

## Логика планирования

Планировщик выбирает заявки с наименьшим числом доступных исполнителей; при
равенстве приоритет получает срочная заявка, затем более узкое временное окно.
Бригада выбирается так, чтобы сохранить больше допустимых вариантов для остальных
заявок. После первичного плана выполняются допустимые прямые вставки и одиночные
перестановки.

Расстояние рассчитывается по Haversine, время в пути — по типовой скорости
транспорта. Это допущение прототипа. Подробности — в [docs/algorithm.md](docs/algorithm.md).

## Проверка

```bash
ctest --test-dir build --output-on-failure
```

Также можно запустить планировщик без интерфейса после сборки:

```bash
./build/route_planner
```

Результат будет записан в `output/plan.json`.

## Ограничения прототипа

- Перепланирование строит новый план для актуального набора заявок и не фиксирует
  уже выполненные визиты.
- Поддержка отмены заявки и недоступности инженера реализована в C++-планировщике,
  но в текущем MVP интерфейс демонстрирует сценарий срочной заявки.
- Маршрут на карте — визуализация; расчётная метрика использует упрощённую модель
  времени и расстояния.
