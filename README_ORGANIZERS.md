# RouteMind — инструкция для организаторов

RouteMind — демонстрационный сервис для распределения выездных заявок между
бригадами. Он учитывает навыки, специализации, транспорт, рабочие смены,
временные окна заявок и расстояние до точки работ.

## Что понадобится

- Python 3.10+;
- CMake 3.20+;
- компилятор C++20: `g++`, `clang++` или `c++`;
- интернет при первой сборке для загрузки технической библиотеки.

## Запуск

Откройте терминал в папке проекта и выполните:

```bash
cd /путь/к/RouteMind-develop
cmake -S . -B build
cmake --build build --parallel
python3 frontend/server.py
```

После появления строки `RouteMind: http://127.0.0.1:8000` откройте адрес
`http://127.0.0.1:8000` в браузере.

Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

Если проект был распакован из архива и CMake сообщает, что папка `build` создана
в другом пути, удалите только папку сборки и повторите запуск:

```bash
rm -rf build
cmake -S . -B build
cmake --build build --parallel
python3 frontend/server.py
```

## Сценарий демонстрации

1. Убедитесь, что выбрана дата **17.08.2026**.
2. Нажмите **«Выгрузить заявки»** — отобразятся заявки и бригады.
3. Нажмите **«Создать маршруты»**.
4. Переключайте бригады над картой, чтобы просматривать рассчитанные маршруты.
5. Выберите заявку в списке, чтобы посмотреть время визита или причину, по
   которой она не была назначена.
6. Для демонстрации нового обращения нажмите **«Новая заявка»**, заполните
   форму, сохраните её и повторно постройте маршруты.

## Что показывает система

- маршруты и порядок визитов каждой бригады;
- время прибытия, начала и окончания работ;
- число задействованных бригад и суммарный пробег;
- неназначенные заявки с причиной: нет координат, подходящей бригады или
  доступного временного окна.

## Важное замечание

В демонстрационном наборе данных часть заявок может остаться неназначенной. Это
ожидаемый результат: некоторые заявки не имеют координат либо не могут быть
выполнены доступными бригадами в заданное время.

Исходные данные хранятся в `data/`. Заявки, добавленные через интерфейс,
сохраняются отдельно в `frontend/user_requests.json`.
