# АЛГОРИТМ: жадная вставка в маршрут + локальное улучшение

*Цель*
----
Построить выполнимый план с максимальным числом назначенных заявок, при полном
выполнении — с минимальным числом задействованных инженеров и затем минимальным
суммарным пробегом.

*Допущение о маршрутизации*
-------------------------
Расстояние между координатами считается по Haversine. Время пути определяется как
distanceKm / speedKmH * 60, где speedKmH зависит от типа транспорта. Это допущение
должно быть явно показано в интерфейсе; позже его можно заменить данными роутера.

*Шаг 1. Подготовка кандидатов*
----------------------------
Для каждой заявки составить список инженеров, удовлетворяющих жёстким ограничениям:
навык, обязательный транспорт, смена и временное окно с учётом пути. Если список пуст,
сразу сформировать понятную причину неназначения.

*Шаг 2. Приоритизация заявок*
---------------------------
Заявки сортируются по ключу:
1) срочная раньше обычной;
2) меньшее windowEnd раньше большего;
3) заявка с меньшим числом допустимых инженеров раньше;
4) исходный ID как стабильный tie-breaker.
Так сначала планируются наиболее критичные и дефицитные работы.

*Шаг 3. Лучшая допустимая вставка*
--------------------------------
Для очередной заявки перебрать каждого допустимого инженера и каждую позицию от 0
до размера его маршрута. После гипотетической вставки пересчитать все последующие
визиты: arrival, start=max(arrival, windowStart), finish. Вставка допустима, если начало
каждой работы попадает в её окно, а окончание последней не превышает shiftEnd.

Из допустимых вставок выбрать минимальную по лексикографическому ключу:
1) не активировать нового инженера;
2) меньший прирост расстояния;
3) меньше суммарного ожидания;
4) более раннее завершение маршрута;
5) меньший engineerId и позиция — для воспроизводимости.

Если вставки нет, заявка остаётся неназначенной. Причина определяется по этапу,
на котором отсеялись кандидаты: навык, транспорт либо доступное время/смена.

*Шаг 4. Локальное улучшение*
--------------------------
После первичного плана несколько раз выполнить улучшения:
- перенести одну заявку в другой маршрут или другую позицию;
- обменять заявки двух маршрутов;
- принять изменение только если оно сохраняет выполнимость и улучшает цель.
Цель сравнивается в порядке: меньше неназначенных срочных, меньше всех неназначенных,
меньше активных инженеров, меньше километров, меньше ожидания.

*Перепланирование*
----------------
Завершённые визиты фиксируются. При отмене заявка удаляется; при недоступности инженера
все его будущие заявки возвращаются в очередь; новая срочная заявка добавляется первой.
Далее повторяется вставка и локальное улучшение только для будущей части плана.
Последним критерием добавляется число изменённых будущих назначений — это сохраняет
стабильность плана, если качество вариантов одинаково.
