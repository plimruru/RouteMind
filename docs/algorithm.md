# Алгоритм RouteMind

## Ограничения

Перед назначением для каждой пары «заявка — бригада» проверяются обязательные
условия: требуемый навык, специализация (если указана), тип транспорта (если
указан), временное окно с длительностью работ и окончание смены. Заявка без
координат сразу получает статус «не назначена».

Расстояние считается по Haversine; время в пути — из расстояния и типовой
скорости выбранного транспорта. Это локальное допущение, поэтому километраж
плана и дорожная линия на карте могут отличаться: карта использует OSRM, когда
он доступен.

## Основной план

На каждом шаге планировщик пересчитывает допустимых кандидатов для всех ещё не
распределённых заявок и выбирает наиболее критичную:

1. меньше доступных бригад;
2. срочная раньше обычной при равенстве;
3. более узкое окно;
4. большая длительность.

Для выбранной заявки бригада выбирается так, чтобы сохранить больше вариантов
для остальных заявок. При равенстве выбирается меньшая стоимость пути и ожидания,
затем более раннее завершение. После первичного распределения выполняются
допустимые прямые вставки и одиночные перестановки, если они позволяют назначить
ранее нераспределённую заявку.

Это эвристика: она стремится назначить максимум заявок, не обещая математический
оптимум.

## Baseline и перепланирование

Для сравнения рассчитывается baseline из ТЗ: заявки идут во входном порядке и
назначаются первой по порядку подходящей бригаде; улучшения не выполняются.
Интерфейс сравнивает километраж с этим вариантом.

Новая заявка создаётся с приоритетом «срочная». При следующем расчёте план
строится заново для актуального набора данных, а интерфейс показывает число
изменённых назначений. Отмена и недоступность инженера поддержаны методом
`Planner::replan` и могут быть подключены отдельными действиями интерфейса.
