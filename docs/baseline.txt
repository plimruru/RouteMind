BASELINE: последовательное назначение без глобальной оптимизации

Назначение
----------
Baseline нужен как прозрачная точка сравнения с основным алгоритмом. Он намеренно
не пытается найти лучший маршрут: заявки и инженеры рассматриваются только в порядке,
в котором они пришли во входном JSON/CSV.

Правила
-------
1. Заявки обрабатываются строго в порядке входного файла.
2. Для каждой заявки инженеры перебираются строго в порядке входного файла.
3. Инженер подходит, если:
   - обладает требуемым навыком;
   - имеет требуемый транспорт, если транспорт указан в заявке;
   - может выполнить заявку после последней уже назначенной ему работы.
4. Время визита рассчитывается так:
   arrival = finish последней работы + время пути;
   start = max(arrival, windowStart);
   finish = start + duration.
   Заявка допустима, если start <= windowEnd и finish <= shiftEnd.
   Для первой заявки маршрут начинается в startLocation инженера.
5. Заявка назначается первому подходящему инженеру. Она добавляется в конец его
   маршрута; порядок посещения равен порядку назначения.
6. Если подходящего инженера нет, заявка получает статус «не назначена».

Причины неназначения
--------------------
- Нет инженера с требуемым навыком.
- Нет инженера с требуемым типом транспорта.
- Есть подходящие по навыку и транспорту инженеры, но заявка не помещается в окно
  или смену с учётом уже построенных маршрутов.

Ограничения baseline
--------------------
Он не меняет порядок уже назначенных визитов, не рассматривает вставку внутрь маршрута,
не сравнивает пробег разных кандидатов и не пытается уменьшить число задействованных
инженеров. Поэтому его результат — нижняя планка для сравнения, а не целевой план.
