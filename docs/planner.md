# Планировщик маршрутов

Этот документ описывает все структуры и функции из
[`cpp/src/planner/Planner.cpp`](../cpp/src/planner/Planner.cpp). Вспомогательные
сущности размещены в анонимном пространстве имён и используются только внутри
этого файла. Время представлено количеством минут от начала суток, расстояние —
километрами.

## Константы

### `kEarthRadiusKm`

Радиус Земли в километрах (`6371.0`). Используется функцией `distanceKm` в
формуле Haversine.

### `kDistanceEpsilon`

Порог сравнения вещественных расстояний (`1e-9`). Нужен, чтобы почти нулевое
расстояние не создавало время пути и чтобы сравнение оценок вставки не зависело
от погрешности вычислений с `double`.

## Внутренние структуры

### `Stop`

Промежуточное представление одной рассчитанной остановки в рабочем маршруте.

| Поле | Назначение |
| --- | --- |
| `request` | Указатель на исходную заявку. |
| `arrivalTime` | Время прибытия инженера. |
| `startTime` | Фактическое начало работы: максимум из времени прибытия и начала окна заявки. |
| `finishTime` | Время завершения работы. |
| `distanceFromPreviousKm` | Расстояние от старта инженера или предыдущей остановки. |

### `WorkingRoute`

Внутренний изменяемый маршрут. Он используется при переборе вариантов вставки;
публичная модель `Route` создаётся только после выбора финального варианта.

| Поле | Назначение |
| --- | --- |
| `engineer` | Инженер, которому принадлежит маршрут. |
| `requests` | Указатели на заявки в порядке посещения. |
| `stops` | Результат расчёта расписания для `requests`. |
| `totalDistanceKm` | Суммарный пробег маршрута. |
| `totalTravelMinutes` | Суммарное время в пути без ожидания. |
| `totalWaitingMinutes` | Суммарное ожидание до открытия временных окон. |

### `Candidate`

Один допустимый вариант вставки текущей заявки в маршрут.

| Поле | Назначение |
| --- | --- |
| `engineerIndex` | Индекс рабочего маршрута в массиве маршрутов. |
| `position` | Позиция, куда вставляется заявка. |
| `route` | Полностью пересчитанный маршрут после вставки. |
| `activatesEngineer` | `true`, если до вставки у инженера не было заявок. |
| `addedDistanceKm` | Прирост расстояния относительно исходного маршрута. |

## Вспомогательные функции

### `radians(double degrees) -> double`

Переводит угол из градусов в радианы. Вызывается только при расчёте расстояния
по географическим координатам.

### `distanceKm(const Point& from, const Point& to) -> double`

Возвращает расстояние между двумя координатами в километрах по формуле Haversine.
Это прямолинейная географическая оценка, а не расстояние по дорожной сети.

### `speedKmH(Transport transport) -> double`

Возвращает принятую среднюю скорость для транспорта:

| Транспорт | Скорость |
| --- | --- |
| `Car` | 30 км/ч |
| `Bicycle` | 15 км/ч |
| `PublicTransport` | 20 км/ч |
| `Pedestrian` | 5 км/ч |

Значение `5 км/ч` также служит защитным значением по умолчанию.

### `travelMinutes(double kilometers, Transport transport) -> int`

Вычисляет длительность поездки: `ceil(расстояние / скорость × 60)`. Ненулевой
переезд всегда округляется вверх до целой минуты. Расстояние не больше
`kDistanceEpsilon` даёт нулевое время пути.

### `hasSkill(const Engineer& engineer, Skill skill) -> bool`

Проверяет, есть ли требуемый навык в списке навыков инженера.

### `compatible(const Request& request, const Engineer& engineer) -> bool`

Проверяет неизменяемую совместимость пары «заявка—инженер»: требуемый навык
должен быть у инженера, а обязательный транспорт (если он указан в заявке)
должен совпадать. Временные ограничения эта функция не проверяет.

### `schedule(WorkingRoute& route) -> bool`

Полностью пересчитывает расписание маршрута и возвращает его выполнимость.

Для каждой заявки рассчитываются:

```text
arrival = finish предыдущей работы + время пути
start   = max(arrival, начало окна)
finish  = start + длительность работы
```

Маршрут отклоняется, если начало работы позже конца её окна или завершение
последней/любой работы выходит за границу смены инженера. При успешном расчёте
обновляются `stops`, пробег, время движения и ожидания. Функция изменяет
переданный `WorkingRoute`.

### `toPublicRoute(const WorkingRoute& route) -> Route`

Преобразует внутренний `WorkingRoute` в модель `Route`, используемую в `Plan`:
переносит идентификатор инженера, метрики маршрута и рассчитанные остановки.

### `betterCandidate(const Candidate& left, const Candidate& right) -> bool`

Возвращает `true`, если `left` лучше `right`. Варианты сравниваются строго в
следующем порядке:

1. не активировать нового инженера;
2. меньший прирост пробега;
3. меньшее суммарное ожидание;
4. более раннее завершение маршрута;
5. меньший ID инженера;
6. меньшая позиция вставки.

Последние два правила делают результат воспроизводимым, если основные показатели
совпадают.

### `unassignedReason(const Request& request, const std::vector<Engineer>& engineers) -> std::string`

Строит объяснение для заявки, которую нельзя назначить. Последовательно отличает
три случая: нет нужного навыка; есть навык, но нет совместимого транспорта; есть
совместимый инженер, но работа не помещается в окна или смены.

## Методы `Planner`

### `Planner::solve(const std::vector<Request>& requests, const std::vector<Engineer>& engineers) -> Plan`

Строит план методом лучшей допустимой вставки.

1. Создаёт по одному пустому `WorkingRoute` на каждого инженера.
2. Сортирует заявки: срочные раньше обычных, затем по раннему окончанию окна,
   числу совместимых инженеров и ID заявки.
3. Для каждой заявки перебирает всех совместимых инженеров и каждую позицию
   вставки в их маршруте.
4. Вызывает `schedule`; невыполнимые варианты отбрасывает, лучший выбирает через
   `betterCandidate`.
5. Если варианта нет, добавляет заявку в `Plan::unassigned` с причиной от
   `unassignedReason`.
6. Преобразует непустые рабочие маршруты в `Plan::routes` и рассчитывает общие
   метрики: число задействованных инженеров и суммарный пробег.

### `Planner::replan(const std::vector<Request>& requests, const std::vector<Engineer>& engineers, const Event& event) -> Plan`

Зарезервирован для перепланирования после события. В текущей реализации не
обрабатывает аргументы и возвращает пустой `Plan`; пометки `(void)` подавляют
предупреждения компилятора до реализации этой логики.
